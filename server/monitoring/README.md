# مراقبة DZ HOOF الأولية

هذا المجلد يجهّز مراقبة محلية اختيارية لـ **DZ HOOF API**. لا يبدأ Prometheus تلقائياً، ولا تُنشر واجهة المراقبة على الإنترنت. تبقى نقطة القياسات محصورة في API باسم `/internal/metrics`، ولا تجيب إلا عند تقديم رمز Bearer صحيح.

> لا تضع مفاتيح SSH أو كلمات مرور أو روابط بث أو رموز اشتراك ضمن الوسوم أو ملفات المراقبة. القياسات الحالية تستخدم فقط `method` و`status_class`، وهي قيم قليلة العدد وآمنة للتجميع.

## خيارات التشغيل

| النهج | النتيجة | التنازل | التكلفة | التعقيد |
| --- | --- | --- | --- | --- |
| **Prometheus محلي اختياري** | البيانات تبقى على VPS، وواجهة المراقبة متاحة محلياً فقط عبر نفق SSH | يحتاج متابعة المساحة والتحديثات | لا توجد خدمة خارجية إضافية | متوسط |
| **خدمة مراقبة مستضافة خارجياً** | لوحة جاهزة ووصول أسهل للفريق | بيانات تشغيلية تغادر VPS وتحتاج حساباً ومفاتيح وصول | تختلف باختلاف المزود | أقل في البداية، أعلى في إدارة الحسابات |

الملفات في هذا المستودع تطبق النهج المحلي الاختياري لأنه يحافظ على بيانات التشغيل داخل الخادم ولا يؤثر في خدمات الإنتاج قبل التفعيل الصريح.

## ما الذي تقيسه النسخة الأولى؟

تجمع هذه الطبقة عدد طلبات HTTP، وأزمنة الاستجابة، وعدد الطلبات الجارية، ومؤشرات اتصال MongoDB وRedis، إضافة إلى مقاييس Node.js القياسية. لا تجمع رابط الطلب ولا هوية العميل ولا أي بيانات من التدفقات.

## خطوات التفعيل بعد استعادة SSH

نفّذ الخطوات التالية من داخل مجلد `server` على VPS فقط بعد تأكيد النسخ الاحتياطي وحالة الخدمات الحالية.

1. أنشئ رمزاً عشوائياً واحفظه خارج Git بصلاحيات مقيدة:

```bash
umask 077
mkdir -p monitoring/runtime
openssl rand -hex 32 > monitoring/runtime/metrics_bearer_token
```

2. انسخ الرمز نفسه إلى المتغير `METRICS_BEARER_TOKEN` في ملف بيئة الإنتاج الحقيقي. لا تضع الرمز في ملف `docker-compose.production.yml` أو في المستودع.

3. حدّث خدمات التطبيق وفق مسار النشر المعتاد للمشروع حتى تلتقط API المتغير الجديد، ثم فعّل خدمة المراقبة الاختيارية فقط:

```bash
docker compose -f docker-compose.production.yml --profile monitoring up -d prometheus
```

4. تحقق محلياً من الحالة عبر خادم VPS؛ لا تفتح المنفذ 9090 في الجدار الناري:

```bash
curl -fsS http://127.0.0.1:9090/-/ready
```

5. للوصول إلى اللوحة من جهاز مسؤول، استخدم نفق SSH بدلاً من تعريض الواجهة للعامة:

```bash
ssh -L 9090:127.0.0.1:9090 root@VPS_HOST
```

بعد فتح النفق، تكون الواجهة على `http://127.0.0.1:9090` في جهاز المسؤول فقط.

## الرجوع الآمن

لإيقاف مراقبة Prometheus من دون تغيير API أو بيانات التطبيق:

```bash
docker compose -f docker-compose.production.yml --profile monitoring stop prometheus
```

يبقى المسار الداخلي غير مفيد من دون رمز Bearer صحيح، ولا يوجد منفذ API جديد مكشوف على المضيف.

## التشغيل والدعم

استخدم الفترة الافتراضية البالغة 30 ثانية واحتفاظاً لمدة 7 أيام في البداية. قبل زيادة زمن الاحتفاظ أو إضافة Grafana أو سجلات مركزية، راجع مساحة القرص والذاكرة والنسخ الاحتياطي على VPS.
