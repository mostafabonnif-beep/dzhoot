# DZ HOOF — قياس الموارد والاستهلاك (Usage Metrics)

> أُضيف في 2026-09-13. الغرض: معرفة **من يحمل الحِمل فعلاً** قبل أي قرار شراء عتاد
> أو فتح الطبقة المجانية للعالم.

## 1. الأرقام الأربعة

| الرقم | المصدر | لماذا يهم |
|---|---|---|
| **المشاهدون الآن** (إجمالي/مجاني/مدفوع/أدمن) | جلسات Redis الحيّة + استنتاج الفئة | هل الطبقة المجانية تجلب حِملاً أم تربح؟ |
| **الاستهلاك** (اليوم GB / آخر دقيقة MB / Mbps) | عدّاد البايتات على مسارات البث | كم يكلّف البث فعلاً (سعة + ترافيك) |
| **الذروة** (مشاهدون / Mbps) | لقطة كل 5 دقائق في مهمة مجدولة | حجم خادمك المطلوب عند الذروة الحقيقية |
| **أعلى القنوات** | metadata الجلسات | إذا كانت 3 قنوات تحمل 80% من الحِمل، هذه فرصتك للكاش/CDN |

## 2. المعمارية

```
upstream-proxy.ts (raw TS/progressive) ─┐
routes/tv.js /hls/:token/:file (remux) ─┤─► createEgressMeter (Transform pass-through)
                                        │        │
                                        │        ▼
                                        │   تجميع في الذاكرة (5 ثوانٍ)
                                        │        ▼
                                        │   Redis: دقيقة/ساعة/يوم + فئة + مسار
                                        ▼        ▼
                              task 'usage-rollup' كل 5 د → UsageDaily (Mongo، TTL 45ي)
```

- **لا شيء على المسار الحرج:** العدّاد `Transform` يمرّر البايت كما هو بلا تخزين مؤقت،
  والتجميع في الذاكرة ثم كتابة واحدة كل 5 ثوانٍ (بدل آلاف الكتابات).
- **Redis اختياري:** إذا غاب، الأرقام تُحسب في الذاكرة لهذه العملية واللوحة تُظهر
  تنبيه «أرقام جزئية» — لا شيء ينهار.
- **الأمان:** الفشل في القياس لا يوقف البث أبداً (كل المسارات داخل try/catch).

## 3. كيف تُستنتج الفئة (free/paid/admin)

بدون تغيير أي شيء في مسار البث أو صيغة التوكن — الفئة تُحسب من الحساب:

1. كود الديمو/المجاني المشترك (`DEMO_TV_CODE`) أو `userId === 'demo'` → **free**
2. حساب `role === 'Admin'` → **admin**
3. `User.freeAccess === true` → **free**
4. اشتراك نشط → **paid**، ولا اشتراك → **free**

النتيجة مخزّنة مؤقتاً 60 ثانية لكل مستخدم/كود، فلا تُرهق قاعدة البيانات.

## 4. واجهات API

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/v1/admin/stats/resources` | لقطة كاملة: `now`, `peak`, `byTier`, `bySource`, `byPath`, `topChannels`, `series` (24 ساعة/ساعة), `history` (30 يوم) |
| GET | `/admin/resources` (لوحة التحكم) | الصفحة: بطاقات + مخطط استهلاك 24 ساعة + أعلى القنوات + تاريخ 30 يوم، تحديث تلقائي كل 15 ثانية |

## 5. المهمة المجدولة

`usage-rollup` (كل 5 دقائق، `USAGE_ROLLUP_INTERVAL_MS` للتغيير):
- تُثبّت ذروة اليوم في Redis (`dz:usage:peak:*`)
- تكتب/تحدّث صف `UsageDaily` لليوم (`$max` للذروة، `$set` للاستهلاك) — تاريخ دائم
  لا يمحوه إعادة تشغيل Redis، وTTL 45 يوماً.

## 6. ما لا يُقاس بعد (بصراحة)

- **اتصالات المزوّد لكل مصدر (Xtream/M3U):** metadata الجلسة لا تحمل `sourceId` بعد.
  الرقم المعروض للمزوّد ≈ عدد المشاهدين المتزامنين. الخدمة تقرأ `session.sourceId` إذا
  أُضيف مستقبلاً بلا تعديل.
- **حصة الترافيك الشهرية من المزوّد السحابي:** تُقرأ من لوحة مزوّد الخادم لا من هنا.
- **بتّات متروّمة (remux) مقابل منسوخة (proxy):** مفصولة في `byPath` (proxy/remux).

## 7. كيف تقرأ الأرقام (قاعدة القرار)

| الحالة | القرار |
|---|---|
| ذروة < 30% من سعة الخادم | لا تشترِ شيئاً |
| Mbps ثابت عالٍ + معالج مشغول (remux) | ترقية CPU أولاً، أو CDN |
| قناة/قناتان تحملان أغلب الحِمل | كاش المقاطع (segment coalescing) ثم CDN |
| مجاني >> مدفوع مع استهلاك عالٍ | حدّد المجاني أو انقله لمصادر مباشرة |
