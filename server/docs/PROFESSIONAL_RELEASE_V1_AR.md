# DZ HOOF IPTV — معيار الإصدار الاحترافي 1.0

## الهدف

هذه النسخة خط إصدار منضبط لمنصة IPTV مخصصة **للمصادر المرخّصة فقط**. هدفها تقديم تشغيل يمكن تتبعه والتحقق منه واستعادته، لا مجرد حاويات تعمل لمرة واحدة.

## ما أُضيف في هذا الإصدار

| المجال          | التحسين                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| تعريف الإصدار   | إصدار حزمة الخادم `1.0.0` مع متغير `APP_VERSION` في بيئة الإنتاج.                                                                     |
| منع أخطاء النشر | أمر `npm run validate:production` يتحقق من ملف البيئة والأسرار وHTTPS وتطابق النطاق والصور المثبتة وشبكة Docker المشتركة قبل التشغيل. |
| انضباط الصور    | يمنع فحص ما قبل الإنتاج استخدام الوسم `latest` أو الوسوم التجريبية؛ استخدم tag إصدار ثابتاً أو digest من SHA-256.                     |
| موثوقية الخدمات | فحوص صحة صريحة لـMongoDB وRedis، وتشغيل API والمجدول بعد جاهزية البيانات.                                                             |
| حماية الموارد   | حدود ذاكرة وحصص حجز لكل من Caddy وAPI والواجهة وMongoDB وRedis والمجدول.                                                              |
| طبقة الويب      | HSTS ورفض sniffing وسياسة إحالات، و`Permissions-Policy` و`X-Robots-Tag` وإزالة ترويسات تعريف الخادم.                                  |

## بوابة الاعتماد قبل الإنتاج

نفّذ هذه الأوامر من مسار `server/` بعد إنشاء `.env.production` بقيم حقيقية وحصرية، وبصلاحية `0600`:

```bash
npm ci
npm run release:check
npm run validate:production
```

ثم تحقّق من Compose دون تشغيله أولاً:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml config
```

لا تبدأ الحاويات ما لم تنجح هذه البوابة كاملة.

## بيانات الإصدار المطلوبة

| المتغير                                 | المطلب                                                                          |
| --------------------------------------- | ------------------------------------------------------------------------------- |
| `APP_VERSION`                           | صيغة إصدار واضحة، مثل `1.0.0`.                                                  |
| `DOCKER_IMAGE` و`DOCKER_FRONTEND_IMAGE` | tag ثابت للإصدار أو digest؛ يمنع `latest`.                                      |
| `DOMAIN`                                | النطاق العام فقط دون بروتوكول.                                                  |
| `APP_URL` و`PUBLIC_BASE_URL`            | يساويان `https://DOMAIN` تماماً.                                                |
| `ALLOWED_ORIGINS`                       | نطاق HTTPS المحدد فقط، وليس `*`.                                                |
| الأسرار                                 | مستقلة وعشوائية وبطول 32 حرفاً على الأقل؛ كلمة مرور الإدارة 16 حرفاً على الأقل. |
| `SUBSCRIPTION_REQUIRED`                 | `true` للإنتاج.                                                                 |

## تجربة آمنة دون إنتاج

1. أنشئ نطاقاً فرعياً أو خادماً تجريبياً، مثل `staging.example.com`، ولا تستخدم نطاق الموقع الحي.
2. انسخ ملف البيئة النموذجي إلى `.env.production` وضع بيانات اختبار وسجّل الصلاحية `600`.
3. استخدم قاعدة بيانات Docker جديدة واسم مشروع Compose مختلفاً، مثل `dzhoof-staging`، حتى لا تشترك النسخة التجريبية في volumes أو حاويات الإنتاج.
4. استورد قائمة M3U مرخّصة تجريبية فقط، ثم اختبر إنشاء مستخدم وربط جهاز وتسجيل الدخول وتشغيل قناة وEPG.
5. راقب `/health/live` و`/health/ready` والذاكرة والسجلات لمدة 30 دقيقة على الأقل.

## نشر متدرج وآمن

1. أنشئ نسخة MongoDB يدوية، وتحقق من الأرشيف وملف SHA-256.
2. احفظ digest الصور السابقة ولقطة من ملف Compose والبيئة **من دون** إرسال الأسرار إلى Git.
3. شغّل الفحوص أعلاه، ثم نفّذ `docker compose ... up -d` فقط بعد الموافقة على الخطة المعروضة.
4. تحقق من `/health/live` و`/health/ready` وتسجيل الدخول واستيراد مصدر M3U مرخّص وربط جهاز Android TV تجريبي.
5. عند ظهور خلل، أعد الصور إلى digest السابقة؛ لا تستعد قاعدة البيانات إلا عند ضرورة مؤكدة وباتباع اختبار الاستعادة الموثق.

## ما لا تقوم به هذه النسخة تلقائياً

لا تغيّر هذه النسخة بيانات الإنتاج، ولا تستورد قنوات، ولا تغيّر DNS، ولا تعيد تشغيل الخادم، ولا تدوّر أسرار الوصول. هذه إجراءات تشغيلية تحتاج موافقة منفصلة لأنها تمس خدمة قائمة.
