# تقرير تدقيق الجاهزية للسوق — DZ HOOF

**التاريخ:** 2026-09-16  
**النطاق:** مستودع GitHub، آخر `main`، CI/CodeQL، API وواجهة الإنتاج، VPS، Docker، النسخ الاحتياطية، عقد تحديث Android، إعدادات Android، والاعتماديات.

## الحكم الصريح

المشروع يعمل في الإنتاج، لكنه **ليس جاهزاً بعد لإطلاق تجاري واسع**. البنية الأساسية مستقرة، لكن هناك فجوات أمنية وتجارية واختبارات أجهزة تمنع اعتبار المنتج جاهزاً للسوق.

## ما تم إصلاحه وتطبيقه

1. إصلاح عقد تحديث APK: أصبح `/api/v1/app/latest` يعيد checksum موثقاً ومتحققاً، ولم تعد حقول integrity فارغة أو روابط الأصول الداخلية ظاهرة.
2. إصلاح تنقيح تقارير الأعطال من كلمات المرور والكوكيز وبيانات Basic Auth وبيانات RTSP وعناوين IPv6. تم دمج PR #302.
3. إصلاح فحص صحة MongoDB. كان الفحص ينفذ `ping` بدون مصادقة رغم تشغيل MongoDB مع `--auth`، وينتج أخطاء Unauthorized كاذبة. أصبح الفحص يستخدم بيانات الاعتماد داخل الحاوية ويثبت أن `ping` نجح.
4. إصلاح صلاحية تشغيل `scripts/security/check-secrets.sh` لتطابق الأمر الموثق.
5. تم دمج الإصلاحات في `main` عند الكوميت `6480e4307c836c48c4d2a5139a3cb3fa1b46e1f1` ونشره ذرّياً على VPS.
6. بعد النشر: `/health` و`/health/ready` سليمان، MongoDB وRedis متصلان، وchecksum الإصدار متحقق.

## الموانع الحرجة قبل السوق

### 1. APK المنشور متأخر عن الكود الحالي — حرج

- الكود الحالي في `main`: `6480e43`.
- الإنتاج يعمل بهذا الكوميت.
- آخر APK عام هو `v1.3.1`، مبني من الكوميت `ece7476`.
- لذلك إصلاحات crash redaction وUpdate API وبعض تغييرات Android الموجودة في `main` لا تصل إلى المستخدمين حتى إصدار APK جديد.

**الإجراء:** إصدار APK جديد من `main` بعد تثبيت سياسة target SDK واختبار جهاز فعلي.

### 2. target SDK قديم بالنسبة إلى Fire TV الحديثة — حرج حسب السوق المستهدف

`android/app/build.gradle.kts` يستخدم `compileSdk = 34` و`targetSdk = 34`. المشروع يعلن دعم Fire TV. Fire OS 16 يتطلب target API 36؛ النسخة الحالية لن تكون مناسبة لإطلاق جديد على أحدث Fire TV. إذا كان التوزيع سيشمل Google Play للهاتف، فـ target 34 أيضاً أقل من المتطلب الحالي لتطبيقات الهاتف.

**الإجراء:** رفع compile/target SDK إلى المستوى المطلوب، تحديث workflow وAGP إن لزم، ثم اختبار Media3 وDRM/التشغيل على الأجهزة المستهدفة.

### 3. المدفوعات غير مفعّلة في الإنتاج — مانع تجاري

الإعداد العام للإنتاج يعيد `chargily.enabled=false`، كما أن إعدادات الدفع الأخرى غير مفعلة. لا توجد طريقة دفع ذاتية مؤكدة للمستخدم.

**الإجراء:** تحديد مزود الدفع النهائي، وضع مفاتيح الإنتاج في Secret Store، تنفيذ اختبار دفع/فشل/إلغاء/إشعار webhook، ثم تفعيل الاشتراك فقط بعد اختبار reconciliation.

### 4. التسجيل والتنبيهات التجارية غير مكتملة — عالٍ

الإنتاج يعيد أن البريد وGoogle OAuth وGitHub OAuth غير مهيأة. هذا يعني أن استعادة الحساب، رسائل التفعيل، والتنبيهات البريدية ليست جاهزة. الإشعارات ليست بديلاً عن البريد عند إطلاق منتج مدفوع.

**الإجراء:** تهيئة SMTP موثوق، اختبار التسجيل واستعادة كلمة المرور، ثم تفعيل OAuth فقط إن كان جزءاً من المنتج.

### 5. لا يوجد تحقق فعلي على أجهزة TV/Fire TV — حرج تشغيلي

CI ينجح في build/lint/unit tests، لكنه لا يثبت:

- تشغيل HLS فعلياً عبر Media3/ExoPlayer.
- التحكم الكامل بالـ D-pad والتركيز.
- pairing عبر PIN/QR.
- تبديل القنوات والمفضلة والبحث وEPG.
- استعادة التشغيل بعد انقطاع الشبكة.
- سلوك الإعلانات والتحديث الذاتي على جهاز حقيقي.
- VOD/Series وwatch-progress عبر جهازين.

**الإجراء:** اختبار قبول موثق على Android TV وFire TV حقيقيين مع مصدر HLS/VOD مصرح به.

## مخاطر أمنية تحتاج إغلاقاً أو تبريراً موثقاً

GitHub CodeQL ما زال يعرض **69 تنبيهاً مفتوحاً**: 12 critical، و56 high، و1 medium. من أمثلتها:

- SSRF في EPG وstream proxy وstream prober وupstream proxy.
- type confusion في معاملات stream proxy والقنوات.
- missing rate limiting/token validation.
- insufficient password hash في `ResellerApiKey`.

قد تكون بعض التنبيهات false positives لأن المشروع يملك `ssrf-guard` مخصصاً، لكن لا يجوز تركها مفتوحة قبل السوق. يجب إما إصلاح كل تنبيه، أو إضافة test/model/suppression مبرر ومراجع لكل حالة.

## VPS والعمليات

### جيد حالياً

- HTTPS صالح حتى 2026-11-16.
- المنافذ الداخلية MongoDB وRedis غير مكشوفة للعامة.
- fail2ban يعمل لـ SSH وHTTP.
- النسخ المحلية وoff-site مفعّلة، وآخر فحص restic نجح.
- النشر ذري مع provenance gate وrollback وsmoke test.
- `/health/ready` يعيد MongoDB وRedis متصلين.

### مشاكل متبقية

1. القرص كان عند حوالي 85% استخدام، وDocker لديه صور وbuild cache قابلة للاسترداد بحجم يقارب 10GB. هذا خطر امتلاء قد يوقف MongoDB أو النشر.
2. النسخ الاحتياطي نجح، لكن لا يوجد في الأدلة الحالية restore drill دوري كامل إلى بيئة منفصلة. نجاح backup لا يثبت قابلية الاستعادة.
3. restic سجّل تحذيراً لأن cache الافتراضي تحت `/root/.cache` للقراءة فقط؛ النسخ نجح، لكن يجب ضبط cache writable لتقليل الضوضاء وتحسين الأداء.
4. سجل MongoDB كان يمتلئ بمحاولات ping غير مصادق عليها؛ تم إصلاح مصدرها في الإصدار المنشور الحالي ويجب مراقبة السجل بعد عدة دورات healthcheck.

## جودة المنتج والهندسة

- `npm audit --omit=dev --audit-level=high`: لا توجد ثغرات dependency عالية.
- backend lint/typecheck/build/tests نجحت، واختبارات frontend نجحت.
- lint يحتوي كمية كبيرة من التحذيرات؛ النجاح ليس نظافة كاملة.
- Next.js يحذر من تقادم convention الخاص بـ `middleware` ويجب الانتقال إلى `proxy` قبل أن يصبح تغييراً قسرياً.
- `scripts/security/check-secrets.sh` كان غير قابل للتنفيذ مباشرة؛ تم إصلاحه.
- الوثائق وبعض README ما زالت تحمل إشارات قديمة وهوية مستودع غير canonical؛ يجب تنظيفها قبل تقديم المشروع لشركاء أو عملاء.

## قرار الإطلاق

**لا أوصي بإطلاق تجاري عام الآن.** الحد الأدنى قبل الإطلاق:

1. إصدار APK جديد من `main` وليس `v1.3.1`.
2. رفع target SDK حسب منصة التوزيع، مع اختبار Fire TV فعلي.
3. إغلاق أو تبرير جميع تنبيهات CodeQL الحرجة والعالية.
4. تفعيل واختبار الدفع والبريد أو الإعلان عن أن النسخة ليست تجارية بعد.
5. تنفيذ اختبار قبول حقيقي للتشغيل وpairing وEPG وVOD/Series والتحديث الذاتي.
6. تنفيذ restore drill موثق وتنظيف Docker disk pressure.
