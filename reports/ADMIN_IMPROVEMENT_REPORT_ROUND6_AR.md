## 1) ما تم تنفيذه في هذه الجولة

الجولة السابقة (5) اقترحت: "تحسين لوحة VOD/Series (إدارة كاملة بدل تصفح فقط)" و"تصدير/استيراد إعدادات كامل". هذه الجولة تنفّذ الاثنين، إضافةً إلى إصلاح سبب جذري يجعل إدارة VOD عديمة الجدوى بدونه.

### أ) إدارة VOD كاملة — الأفلام والمسلسلات (الميزة الأهم)

كانت صفحات الأفلام (66,866 فيلم) والمسلسلات (16,791 مسلسل) **تصفحاً فقط** — لا تعطيل، لا حذف، لا إدارة. أصبحت الآن إدارة كاملة.

**الباكند — راوتر جديد `routes/admin-vod.js` (`/api/v1/admin/vod`):**

| الطريقة | المسار | الوظيفة |
|--------|-------|---------|
| PATCH | `/movies/bulk` + `/series/bulk` | تفعيل/تعطيل جماعي بالمعرّفات (سقف 2000، التعطيل يتطلب تأكيداً) |
| DELETE | `/movies/bulk` + `/series/bulk` | حذف جماعي بالمعرّفات (يتطلب تأكيداً) |
| PATCH | `/movies/bulk-by-category` + `/series/bulk-by-category` | تفعيل/تعطيل تصنيف كامل دفعة واحدة (مثال: إخفاء كل "BG - بلغاريا فيلم" بضغطة) — مع نطاق مصدر اختياري |
| DELETE | `/movies/bulk-by-category` + `/series/bulk-by-category` | حذف تصنيف كامل |
| PATCH | `/movies/:id` + `/series/:id` | تفعيل/تعطيل عنصر واحد |
| DELETE | `/movies/:id` + `/series/:id` | حذف عنصر واحد |

- **حذف المسلسلات متسلسل**: حذف مسلسل يحذف مواسيه وحلقاته تلقائياً (لا سجلات يتيمة). التقرير يعيد العدد المحذوف من كل نوع.
- كل المسارات `requireAuth + requireAdmin`، كل عملية مُدوَّنة في سجل التدقيق (`bulk_enable_movies`, `delete_series`... إلخ).
- مسارات `bulk` مسجَّلة **قبل** `/:id` لمنع حجب المسار (نفس خطأ الجولة 3 الذي أُصلح).

**الواجهة — مكوّن مشترك جديد `vod-admin-shell.tsx`:**
- مربعات اختيار لكل بطاقة/صف + "تحديد الكل" في عرض القائمة.
- شريط أدوات يظهر عند التحديد: **تفعيل / تعطيل / حذف / إلغاء التحديد** (مع تأكيدات).
- شريط **عمليات التصنيف الكامل** يظهر عند اختيار تصنيف محدد: تفعيل/تعطيل/حذف الكل.
- أزرار فردية على كل عنصر (تعطيل/تفعيل + حذف) مع تأكيدات.
- شارة "معطّل" الحمراء على العناصر غير النشطة + تعتيم بصري.
- رسالة نتيجة (نجاح/خطأ) بعد كل عملية. التحديد يُمسح تلقائياً عند تغيير الصفحة/الفلاتر.
- صفحتا `movies-page-shell` و`series-page-shell` أُعيد بناؤهما فوق هذا المكوّن (حذف ~570 سطر تكرار).

### ب) إصلاح جذري: التعطيل اليدوي كان يُمحى عند كل مزامنة

هذا هو **السبب الذي يجعل إدارة VOD بلا معنى بدونه**:
- `upsertMovie` و`upsertSeries` في `xtream-service.ts` كانا يضبطان `isActive: true` داخل `$set` عند كل مزامنة.
- النتيجة: لو عطّل المشرف فيلماً يدوياً، فأول مزامنة مجدولة (تعمل يومياً) **تعيد تفعيله صامتاً** — فيعود المحتوى المُخفى.
- **الإصلاح**: نقل `isActive: true` إلى `$setOnInsert` — يُفعَّل افتراضياً عند الإدراج الأول فقط، وعند التحديث تُحترم القيمة الحالية (تعطيل يدوي أو تنقية سابقة).

### ج) تصدير/استيراد إعدادات التطبيق

**الباكند — `admin-app-settings.js`:**
- `GET /export`: يصدّر الإعدادات القابلة للضبط كملف JSON قابل للتنزيل. **يستبعد** حالات إيقاف المهام المجدولة (`scheduler_enabled_*`) وأعلام التطبيق (`app`) لأنها حالة تشغيلية وليست إعداداً — فلا تُعيد النسخة إحياء مهمة أوقفتَها عن قصد.
- `POST /import`: يستعيد من نسخة JSON (يقبل إما كائن الإعدادات الخام أو حمولة التصدير الكاملة `{settings:{...}}`). المفاتيح غير المعروفة **تُتخطَّى ولا تُكتب أبداً** (تحققنا أن `rogue_key` لم تُكتب).
- كلاهما مُدوَّن في سجل التدقيق.

**الواجهة:** قسم "نسخ الإعدادات الاحتياطي" جديد في صفحة الإعدادات — زر **تصدير** (ينزّل JSON) وزر **استيراد** (اختيار ملف + تأكيد قبل الاستبدال)، مع رسائل توضيحية بالعربية/الفرنسية/الإنجليزية.

### د) إصلاح تسرب تشغيل الحلقات

- `tv.js` كان يتحقق أن الحلقة نشطة (`isActive !== false`) لكن **لا يتحقق من المسلسل الأم**.
- الآن: حلقة مسلسل معطَّل تُرجِع 404 (`{isActive: {$ne: false}}` يحافظ على تشغيل الوثائق القديمة التي لا تحمل الحقل).
