# تقرير تسليم: تنقية عرض كتالوج القنوات

**المشروع:** DZ HOOF IPTV
**الفرع:** `feat/catalog-presentation-normalization`
**التاريخ:** 27 أغسطس 2026
**الحالة:** جاهز للمراجعة البرمجية. لم يُدمج في `main` ولم يُنشر على VPS ولم تُجر أي كتابة على قاعدة الإنتاج ضمن هذا العمل.

## الهدف والنطاق

يعالج هذا التغيير تجربة المشاهد فقط. فهو يمنع ظهور القنوات التي تحمل علامة `###` المتكررة أو علامة اسم المورد `NEO` في حقول العرض، ويحوّل عنوان المجموعة الخام إلى تصنيف عرض محايد بصيغة **البلد أو المنطقة · الفئة**. لا يغير التغيير اسم السجل في MongoDB ولا يحذف metadata المصدر أو معلومات الحقوق أو سجلات التدقيق؛ تبقى هذه البيانات محفوظة وقابلة للمراجعة من مسارات الإدارة المخولة.

> **قاعدة التشغيل:** الاستبعاد من واجهة المشاهد فوري ودفاعي في الـ API. الأرشفة في MongoDB عملية لاحقة اختيارية، محمية بمراجعة تقرير ونسخة احتياطية وتأكيدين صريحين.

| جانب | القرار المنفذ |
|---|---|
| علامات `###` في الاسم أو `tvgName` أو المجموعة أو الصورة | لا تُرسل لأي مخرج مشاهد |
| علامة `NEO` المنفصلة في الحقول المرئية | لا تُرسل لأي مخرج مشاهد |
| وسم جودة `4K` وحده | لا يُحجب آلياً؛ الجودة ليست دليلاً كافياً على المورد |
| اسم قناة قانوني مثل علامة البث نفسها | لا يُحذف لمجرد كونه علامة تجارية للقناة |
| `metadata.source` و`xtreamSourceId` و`xtreamStreamId` | لا تُسلسل في مخرجات المشاهد |
| سجلات المصدر والحقوق والتدقيق | تبقى كما هي داخل قاعدة البيانات والإدارة |

## نتيجة تدقيق البيانات السابقة

تم إجراء فحص قراءة فقط على الإنتاج قبل كتابة الكود. كان الكتالوج المشترك النشط يحتوي على **16,640** قناة. وُجدت **392** قناة تحمل نمط `#{3,}` في الاسم أو `tvgName`، ووجدت أربع قنوات تتضمن `neo` في حقول العرض. لا ينبغي جمع الرقمين كحذف نهائي مؤكد قبل تشغيل التقرير الجديد، لأن المجموعة قد تتداخل ولأن الأداة تفحص أيضاً المجموعة والشعارين. كذلك كانت `metadata.country` غير مكتملة في الإنتاج، بينما احتوت `channelGroup` غالباً على بادئة بلد/منطقة موثوقة؛ لهذا يستخرج التصنيف من البادئات فقط ولا يخمّن دولة دقيقة عند غياب بادئة معروفة.

| إشارة البيانات | النتيجة | سياسة العرض |
|---|---:|---|
| قنوات كتالوج نشطة | 16,640 | خارج نطاق الحذف المباشر |
| رمز `###` في حقول الاسم المفحوصة سابقاً | 392 | حجب فوري في الـ API؛ مرشحة للأرشفة اللينة بعد مراجعة |
| `neo` في حقول العرض | 4 | حجب فوري؛ تراجع في تقرير مستقل قبل الأرشفة |
| `4k` في الاسم أو الاسم التلفزيوني أو المجموعة | 126 | تبقى مرئية، ما لم تحمل أيضاً علامة حجب واضحة |
| `metadata.country` مملوءة | 0 | لا يعتمد التصنيف على تخمين metadata فارغة |

## سبب استمرار المشكلة في اللقطات

أظهر الفحص القرائي على VPS أن حاوية API المنشورة لا تحتوي بعد ملفات أو علامات تنفيذ طبقة `catalog-presentation`، وأن شجرة `/opt/dzhoot` ليست نسخة Git قابلة لتحديد الالتزام منها. لذلك ما زالت API الحالية ترسل عناوين `#####` القديمة إلى التطبيق. هذا يفسر النص الظاهر في اللقطات ولا يعني فشل الفلتر الموجود في طلب المراجعة؛ الإصلاح لم يُنشر بعد.

كما أكد تتبع واجهة Android أن الصورة الذهبية **4K** في الجزء العلوي ترسمها `ExoPlayer` داخل مساحة الفيديو. أي أنها صورة أو شاشة واردة من دفق القناة نفسه وليست شعاراً ثابتاً لتطبيق DZ HOOF. لا يمكن إخفاء محتوى الدفق بصورة صحيحة من واجهة التطبيق؛ الحماية العملية هي منع القناة ذات العلامة من المزامنة والاختيار والتشغيل، وهو ما ينفذه الإصلاح. بعد التحديث، يلزم إيقاف التشغيل الحالي ثم إجراء مزامنة قنوات أو إعادة فتح التطبيق كي تستبدل قاعدة Room القائمة القديمة بالقائمة المنقاة.

## ما تم تنفيذه

أضيفت طبقة مركزية في `server/backend/src/utils/catalog-presentation.js`. تحدد هذه الطبقة القنوات المحجوبة، وتبني استعلام MongoDB مطابقاً لسياسة الحجب، وتستخرج منطقة أو دولة من بادئة موثوقة مثل `DZ|` أو `FR|` أو `AR|`، ثم تستنتج فئة عرض محددة من النصوص المعروفة مثل الرياضة والأخبار والأفلام والأطفال. إذا غابت دلالة موثوقة، تستخدم **دولي · عام** بدلاً من اختراع بلد أو فئة.

تم ربط الطبقة بمخرجات `/channels` و`/channels/grouped` و`/channels/search` والقناة الفردية وبدائلها، وبقوائم التلفاز وEPG وM3U. يستبدل `channelGroup` المعروض بعنوان عرض موحد، ويرتب الكتالوج بحسب البلد ثم الفئة ثم اسم القناة. كما جرى تغيير مفاتيح التخزين المؤقت بإصدار `presentation-v1` حتى لا تعود الاستجابات المخزنة ذات العناوين الخام بعد النشر. ويمنع مولد M3U كذلك حقل `catchup-source` الخام، لأنه قالب رابط علوي قد يحمل بيانات اعتماد؛ يبقى للمشاهد وصف capability وأيام catch-up فقط.

تُسقط projection العامة مفاتيح المصدر، مع ترويسات التشغيل ومفتاح DRM وخصائص البدائل الداخلية. لا تمس هذه العملية المستند المخزن، ولا نقاط الإدارة التي تحتاج provenance لأعمال الامتثال والمراجعة.

| المسار أو المكوّن | التغيير |
|---|---|
| `routes/channels.js` | فلترة وعرض وترتيب ونظافة حقول لجميع قوائم العميل وبحثه وتجميعه |
| `routes/tv.js` | فلترة وتقديم عرض محايد لقائمة التلفاز وEPG مع استمرار روابط التشغيل المرمدة |
| `routes/user-playlist.js` | منع إعادة العلامات عبر قائمة المستخدم وبدائلها |
| `models/User.ts` | منع إعادة القنوات ذات العلامات في M3U المخصص للمستخدم |
| `models/Channel.ts` | فلترة التصدير الموروث وعنوان مجموعة محايد في M3U إن فُعّل هذا المسار |
| `catalog-presentation-audit.ts` | تدقيق جاف وأرشفة لينة محمية، بلا حذف فعلي |
| `CatalogPresentationPolicy.kt` | حاجز Android أخير يحجب العلامات في الاسم والمجموعة والشعار قبل التخزين أو العرض |
| `ChannelRepositoryImpl.kt` | ينقي قراءة Room ونتائج البحث والقناة الفردية، ويستبدل cache بالقنوات المرئية فقط عند كل مزامنة |

## أداة التدقيق والأرشفة

الأمر التالي يولد تقرير JSON بصلاحية `0600` يحتوي على المعرفات والأسباب فقط. لا يسجل روابط البث أو بيانات الاعتماد أو عناوين القنوات الخام أو شعار المورد.

```bash
cd /opt/dzhoot/server/backend
npm run audit:catalog-presentation
```

بعد أخذ `mongodump` ناجح، ومراجعة التقرير، والحصول على موافقة تغيير منفصلة، يمكن تنفيذ الأرشفة اللينة فقط بالأمر التالي. يغيّر الأمر `isActive=false` للقنوات المطابقة في الكتالوج المشترك، ولا يحذف المستندات ولا provenance ولا تاريخ الحقوق.

```bash
npm run audit:catalog-presentation -- --apply --confirm
```

لا يجب تشغيل أمر `--apply --confirm` في هذه المرحلة أو ضمن CI أو النشر التلقائي. فلتر API يجعل القنوات غير مرئية بالفعل عند نشر الكود، ولذلك ليست هناك حاجة ملحة لمخاطرة كتابة جماعية قبل استيفاء النسخ الاحتياطي والمراجعة.

## التحقق المنجز

اختبر التغيير محلياً على الفرع باستخدام تبعيات المشروع الموجودة. نجحت اختبارات طبقة العرض واختبارات نموذج M3U ذات الصلة، بإجمالي 12 اختباراً. نجح `typecheck`. نجح `lint` من دون أخطاء؛ توجد 476 تحذيراً متراكماً في المشروع وخارج نطاق هذا الفرع. نجح كذلك `git diff --check`، وفحص نمط الأسرار على ملفات التغيير لم يجد متغيرات سرية أو روابط اتصال تحمل بيانات اعتماد. كما نجح اختبار Android المحدد لحاجز cache بعد ضبط مسار SDK المحلي. اكتمل تشغيل CI السابق لطلب المراجعة بنجاح، وسيعاد تشغيله بعد دفع هذا التحديث الأخير.

## ما يحتاج قرار المراجعة أو العمل اللاحق

قبل فتح النشر إلى الإنتاج، يلزم فحص بصري على Android TV وواجهة الويب بعينة متعددة اللغات، لأن التصنيف الحتمي المبدئي يغطي البادئات المعروفة فقط. ينبغي أيضاً مراجعة قائمة **دولي · عام** وتحديد قواعد قانونية للبلدان والفئات التي لا تحمل بادئة موثوقة، بدلاً من تخمين بلد أو تبديل اسم قناة مرخصة.

في اللحظة التي كتب فيها هذا التقرير لم تكن حاوية الإنتاج تحمل الفلتر؛ لذلك يجب نشر هذا الإصلاح قبل توقع اختفاء اللقطات المشابهة. بعد نجاح CI لهذا التحديث، تؤخذ نسخة MongoDB جديدة ويُنشر الكود عبر المسار المعتمد، ثم يجرى فحص بصري بتطبيق محدث ومزامنة قنوات جديدة. وبعد التحقق من النسخة الاحتياطية ونجاح الشاشات الأساسية، يمكن تشغيل التدقيق الجاف ثم اتخاذ قرار الأرشفة اللينة في نافذة تغيير مستقلة مع خطة استعادة موثقة.
