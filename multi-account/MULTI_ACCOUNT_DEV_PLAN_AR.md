# DZ HOOF — خطة التطوير متعدد الحسابات (MoClaw)

آخر تحديث: 2026-08-18

## 1. الفكرة الأساسية

التطوير يتم بالتوازي عبر عدة حسابات على moclaw.ai/chat. كل حساب = **مطوِّر مستقل** له ملفه المحدد (ملف `<account>-brief.md`). التنسيق بين الحسابات يتم عبر **مستودع GitHub مشترك** (مرجع أساسي واحد) — وليس عبر الدردشة.

## 2. قاعدة ذهبية (لا نقاش فيها)

**لا تُرسل أي أسرار عبر الدردشة أو المجموعات:** كلمات مرور، مفاتيح Xtream، keystore، أكواد تفعيل، بيانات `.env`.
- الأسرار الحقيقية → `GitHub Secrets` أو `.env` على الـ VPS مباشرة.
- المستودع يحتوي `.env.example` فقط بقيم وهمية.
- كل حساب يعمل بقيم محلية (test values) ولا يحتاج الأسرار أصلًا.

## 4. بروتوكول العمل الأسبوعي

1. كل حساب يعمل على فرعه فقط من `develop` — لا مساس بفروع الآخرين.
2. قبل الكود: اقرأ `AGENTS.md` ثم `PROJECT_ROADMAP.md` ثم `server/PROJECT_STATUS.md`.
3. تغييرات صغيرة مركزة + Conventional Commits (`feat:`/`fix:`/`docs:`...).
4. PR صغير موثق (ماذا/لماذا/الاختبار/تغيير DB أو API/أسرار/رخصة).
5. CI إلزامي أخضر قبل الدمج (backend + android + frontend).
6. حساب التكامل يراجع ويدمج ويحذف الفرع، ويحدّث حالات الخارطة.
7. أي خلاف تقني → GitHub Issue للنقاش، والقرار النهائي للمستخدم.

## 5. الجلسة الأولى لكل حساب (نفس الخطوات)

1. اربط GitHub: Workspace → Connectors → GitHub → Allow (اختر repo المشروع).
2. افتح ملف البريف الخاص بك `<account-brief.md>` (ارفع الحزمة أو انسخه).
3. `git clone` المستودع → `git checkout -b <فرعك> origin/develop`.
4. ثبّت الاعتماديات (حسب README) → نفّذ أول مهمة في قائمتك.
5. أول إنجاز → PR صغير → أبلغ المستخدم في الدردشة برابط الـ PR.

## 6. إذا لم يتوفر GitHub بعد (بديل مؤقت)

- المستخدم يرسل الأرشيف نفسه (tar.gz) لكل حساب.
- كل حساب يشتغل على نطاقه، ثم يُصدّر تغييراته باسم واضح: `dzhoof-<حساب>-<التاريخ>.tar.gz`.
- حساب التكامل يجمع التغييرات يدويًا (وضع مؤقت فقط — GitHub أسرع وأأمن).

## 7. البدء — 3 قرارات من المستخدم

- [ ] مستودع GitHub: جديد (أجهّز الهيكل) أم موجود (اذكر الرابط)؟
- [ ] ربط GitHub connector على حساب التكامل (الأول)؟
- [ ] تثبيت المسارات على الحسابات (الجدول أعلاه) أم تعديل التوزيع؟
