# دليل إصدار جاهزية الإنتاج: device access token ودورة حياة القنوات

**الحالة:** مسودة إصدار للمراجعة فقط. لا يسمح هذا الدليل بالدمج أو النشر تلقائياً، ولا يغيّر إعدادات الإنتاج بنفسه.

## الغرض

ينقل هذا الإصدار المصادقة في تطبيق Android TV من رمز القناة القصير إلى **device access token** عشوائي بطول 256-bit، يحفظ الخادم بصمته فقط ويستطيع إبطاله عند حذف الجهاز أو تدوير رمزه. كما يضيف دورة حياة صريحة للقنوات، فلا يصل العملاء إلا إلى القنوات ذات الحالة `active`.

> لا تنفّذ هذه الخطوات قبل نجاح CI، مراجعة التغييرات، ووجود APK متوافق مبني من هذا المرجع. التطبيق القديم لا يملك device access token؛ تشغيله مع تعطيل التوافق القديم سيؤدي إلى فشل تشغيله.

| التغيير | الأثر التشغيلي | الحماية المطبقة |
|---|---|---|
| `X-Device-Token` | اعتماد Android TV الأساسي | 256-bit، بصمة SHA-256 فقط في MongoDB، قابل للدوران والإبطال |
| `ALLOW_LEGACY_TV_CODE=false` | يمنع رمز القناة من مصادقة API | افتراضي آمن؛ يستخدم فقط خلال ترحيل مضبوط |
| `ALLOW_LEGACY_PLAYBACK_TOKEN=false` | يمنع tokens القديمة المقيدة برمز القناة | لا يصدر APK الجديد tokens من هذا النوع |
| `lifecycleStatus` | يمنع القنوات غير المعتمدة من الظهور | لا تظهر إلا `active` في الكتالوج والقوائم |
| الأرشفة | يستبدل حذف القناة من واجهة الإدارة | قابل للاسترجاع مع سجل تدقيق |

## متطلبات ما قبل الإصدار

يجب أن تكون نسخة احتياطية MongoDB ناجحة وحديثة، وأن تكون صور API وFrontend مستقرة، وأن يكون `FORCE_UPDATE_ADMIN_PASSWORD` **غير مضبوط**. هذا المتغير مخصص فقط لتدوير كلمة مرور مقصود ومعلن؛ لا يجوز وضعه ضمن إعدادات تشغيل دائمة.

ينبغي أيضاً تحضير APK جديد يمر بتجميع `OfficialRelease` ويحتوي على التغييرات التالية: تخزين token في `SecurePreferences`، وإرسال `X-Device-Token` إلى API، وعدم الاعتماد على `channelListCode` في استجابة التنشيط.

| فحص تمهيدي | نتيجة مقبولة |
|---|---|
| نسخة MongoDB | لقطة ناجحة يمكن استرجاعها ومؤرخة قبل الإصدار |
| صحة API وFrontend | `/health` و`/health/ready` يعيدان نجاحاً |
| CI | Backend وFrontend وAndroid باللون الأخضر |
| APK | حزمة موقعة بالإصدار الجديد وتثبت كتحديث |
| متغيرات الترحيل | لا تفعّل `ALLOW_LEGACY_*` إلا عند ضرورة انتقالية موثقة |

## ترتيب التنفيذ المعتمد

ابدأ بإخراج الحزمة المعتمدة وتحقق من بصمتها. قبل تبديل صور التطبيق، شغّل migration دورة الحياة في وضع المعاينة؛ الكود القديم يتجاهل الحقل الجديد، ولذلك يعد هذا الإجراء آمناً قبل التحويل.

```bash
cd /opt/dzhoot/server/backend
npm run migrate:channel-lifecycle
```

راجع الأرقام الظاهرة في وضع المعاينة. ينبغي أن تفسر نتيجة `active` و`degraded` و`disabled` جميع صفوف الكتالوج القديمة. لا تعتمد على تخمين؛ إذا بدت الأرقام غير منطقية، أوقف الإصدار وافحص المصدر والحالة قبل `--commit`.

بعد أخذ نسخة MongoDB إضافية مباشرةً، طبّق migration:

```bash
npm run migrate:channel-lifecycle -- --commit
```

انشر الحزمة الذرية المعتمدة وفق آلية المشروع المعتادة. بعد أن تصبح حاويات API وFrontend سليمة، انشر APK الجديد أولاً ضمن اختبار داخلي على جهاز واحد. نفّذ تنشيطاً جديداً أو دوراناً مصادقاً للجهاز وتأكد من وجود `X-Device-Token` في طلبات API من دون طباعته في السجلات.

فقط بعد نجاح اختبار جهاز داخلي حقيقي، أبقِ القيم التالية في إعداد الإنتاج:

```dotenv
ALLOW_LEGACY_TV_CODE=false
ALLOW_LEGACY_PLAYBACK_TOKEN=false
```

لا تُخزّن هذه القيم أو أي token أو كلمة مرور في Git.

## تحقق ما بعد الإصدار

اختبر حساباً باشتراك فعال، وحساباً منتهياً، وجهازاً تم إبطاله من لوحة الإدارة. يجب أن يحصل الحساب الفعال على الكتالوج والقناة النشطة فقط. الحساب المنتهي يجب أن يتلقى 403 من playlist وEPG وplayback، والجهاز المحذوف يجب أن يتلقى 401 من API وأن تتوقف URLs التشغيل المرتبطة به.

| سيناريو | النتيجة المطلوبة |
|---|---|
| قناة `pending_verification` | لا تظهر للعميل ولا يصدر لها URL تشغيل |
| قناة `active` ومصدر موثق | تظهر وتصدر URL تشغيل مقيّداً بالجهاز |
| اشتراك منتهٍ أو ملغى | رفض موحد من playlist وEPG وplayback |
| إزالة الجهاز | token لا يعود صالحاً وURLs السابقة ترفض |
| أرشفة قناة | تختفي من العملاء وتبقى في قاعدة البيانات للمراجعة |

راقب لوحة `/admin/stats/stream-health` للتحقق من أرقام `lifecycleActive` و`lifecyclePending` و`lifecycleDegraded` و`lifecycleArchived`. لا تجعل القناة `active` لمجرد اكتمال الاستيراد؛ يلزم نجاح تحقق المصدر والصحة حسب سياسة التشغيل.

## الاسترجاع

إذا ظهر عطل في APK الجديد قبل نشره العام، أوقف التوزيع وارجع إلى APK السابق. إذا كان سبب العطل هو ترحيل جهاز قائم ولم تتوفر حزمة جديدة بعد، يمكن تشغيل أحد مفاتيح التوافق بشكل مؤقت ومحدد زمنياً فقط، ثم إعادة تعطيله فور إتمام التحديث. يجب تسجيل سبب الاستثناء ووقت انتهائه في سجل التشغيل.

إذا ظهرت أرقام دورة حياة خاطئة بعد migration، يمكن استرجاع MongoDB من النسخة السابقة أو تصحيح الحالات إدارياً؛ لا تستخدم حذف القنوات كحل أول. الأرشفة والتعطيل قابلان للاسترجاع، أما purge الفعلي فيتطلب إجراء صيانة مستقل وموافقة صريحة.

## حدود هذا الإصدار

لا يثبت هذا الإصدار ملكية حقوق البث ولا يعالج رفض مصدر خارجي لمقاطع HLS. يجب أن يبقى كل مصدر محتوى مرخصاً وموثقاً، وأن تكون نتيجة التحقق من المصدر جزءاً من قرار تفعيل القناة.
