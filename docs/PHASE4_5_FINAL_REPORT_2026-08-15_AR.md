# DZ HOOF — تقرير المرحلة 4 و5

**التاريخ:** 2026-08-15
**المرحلة:** VOD وSeries + الاشتراكات وأكواد التفعيل
**الحالة:** مدمجة في `main` عبر [PR #44](https://github.com/merci1994dz/dzhoot/pull/44)

## 1. الملخص

تم تنفيذ حزمة إصلاح وتحسين مركزة على مرحلتي VOD وSeries والاشتراكات وأكواد التفعيل، مع الحفاظ على قاعدة المشروع القانونية: لا تُضاف أي قنوات أو مصادر جاهزة، ولا تُكشف روابط البث أو أسرار مزودي الخدمة، ولا يُستخدم إلا مصدر يملك المشغل حق استخدامه.

شملت الحزمة حماية عقود المحتوى، منع تشغيل محتوى تابع لمصدر Xtream غير فعال، إضافة شاشة تفاصيل الفيلم، تحسين تفاصيل المسلسلات والمواسم والحلقات، Continue Watching محليًا عبر Room، عرض انتهاء الاشتراك بصورة صحيحة، حماية activation/redeem من التخمين المتكرر، وتعريب تجربة الاشتراك وأخطاء التشغيل الأساسية.

## 2. ما تم إنجازه في VOD وSeries

| العنصر | الحالة والنتيجة |
|---|---|
| نماذج المحتوى | نماذج Movie وSeries وSeason وEpisode موجودة ومستخدمة في الاستيراد والمسارات. |
| تفاصيل الفيلم | إضافة `MovieDetails` في Android مع Poster والوصف والتصنيف والسنة والتقييم والمدة وزر تشغيل. |
| تفاصيل المسلسل | فتح SeriesDetails والمواسم والحلقات مباشرة من البحث أو الكتالوج. |
| البحث | نتائج الأفلام تفتح تفاصيل الفيلم، ونتائج المسلسلات تفتح تفاصيل المسلسل بدل الانتقال المباشر للتشغيل. |
| حماية الحلقات | التحقق من وجود Season، وارتباطه بـSeries الصحيح، وكون Series فعالًا قبل إرجاع الحلقات. |
| حماية المصدر | منع تشغيل Movie أو Episode إذا كان مصدر Xtream غير فعال أو إذا كان parent غير صالح. |
| روابط البث | لا تُعاد `streamUrl` في catalog أو episodes، ويستمر التشغيل عبر playback authorization والتوكن المشفر. |
| Continue Watching | حفظ واستعادة موضع الفيلم أو الحلقة محليًا عبر Room الموجود، دون Room migration جديدة. |
| retry | إصلاح retry لتفاصيل المسلسل والحلقات بدل إعادة المستخدم إلى الشاشة السابقة. |
| RTL والعربية | تعريب أزرار VOD ورسائل التحميل والفشل والمواسم والمزيد وإعادة المحاولة. |

يحفظ التطبيق موضع VOD دوريًا أثناء التشغيل وقبل مغادرة الشاشة، ويستعيده عند فتح المحتوى مرة أخرى، ويحذفه عند اكتمال الفيلم أو الحلقة. ما زالت مزامنة الموضع عبر الأجهزة وسجل المشاهدة الحسابي غير منفذين، لأنهما يحتاجان عقدًا مستقلًا وسياسة خصوصية واضحة.

## 3. ما تم إنجازه في الاشتراكات وأكواد التفعيل

تم تقوية المرحلة 5 دون تغيير عقد التفعيل الناجح. عند انتهاء الاشتراك، يعرض `GET /api/v1/me/subscription` الحالة `EXPIRED` بدل تقديم السجل كاشتراك فعال. وتستمر صلاحية التشغيل في الاعتماد على `expiresAt > now`، مع إعادة فحص الاشتراك عند proxy playback لمنع استمرار الوصول بعد الانتهاء.

أضيفت حماية rate limiting لمسار `POST /api/v1/activation/redeem`: يسمح النظام بعشر محاولات لكل مستخدم خلال عشر دقائق، ثم يعيد HTTP 429 مع `ACTIVATION_RATE_LIMITED` و`Retry-After`. لا يتم تخزين الكود الخام، وتبقى محاولات التفعيل مسجلة لأغراض التدقيق دون كشف بيانات حساسة.

| كود الخطأ | السلوك في Android |
|---|---|
| `INVALID_CODE` | كود تفعيل غير صالح. |
| `CODE_ALREADY_USED` | الكود مستخدم سابقًا. |
| `CODE_EXPIRED` | انتهت صلاحية الكود. |
| `PLAN_UNAVAILABLE` | الخطة غير متاحة. |
| `DEVICE_LIMIT_REACHED` | تم بلوغ حد الأجهزة، مع توجيه المستخدم لحذف جهاز. |
| `SUBSCRIPTION_EXPIRED` | الاشتراك منتهٍ ويجب تفعيل كود جديد. |
| `ACTIVATION_RATE_LIMITED` | تم تجاوز محاولات التفعيل ويجب الانتظار. |

تم تمرير أكواد الخطأ من Backend إلى Android بدل تحويلها إلى رسائل HTTP عامة، كما عُرّبت شاشة الاشتراك وعناصر الخطة والأجهزة والأزرار ورسائل النجاح والفشل.

## 6. ما تبقى والأولوية التالية

الأولوية الأولى هي قبول Android TV الفعلي: إنشاء APK Debug، اختبار PIN وQR، تشغيل فيلم وحلقة وقناة، فحص EPG، تبديل المحتوى، التحقق من resume، اختبار انتهاء الاشتراك، وتأكيد أخطاء device limit وactivation rate limit على D-pad.

بعد قبول Android، تكون الأولوية الثانية تنفيذ مزامنة Continue Watching عبر الحساب والأجهزة، مع تحديد سياسة الاحتفاظ بالبيانات وحدود الخصوصية. بعدها يضاف اختيار الصوت والترجمة عند توفرهما، ثم شاشة تفاصيل فيلم أوسع إن احتاجت بيانات Xtream، ثم DVR/Timeshift الكامل في مرحلة مستقلة.

يُفضّل عدم دمج PRs الإنتاج القديمة بالجملة. إذا كان activation/subscription التجاري أو production hardening من PR #30 مطلوبًا، يستخرج منه كل جزء في PR مستقل مع اختبارات API وAndroid، لأن `main` الحالي يحتوي نسخًا أحدث من ملفات Android وCI وplayback.

## 7. قرار التنفيذ المقترح

النسخة الحالية أصبحت أقوى في حماية VOD وSeries وفي وضوح الاشتراك، لكنها لا تُعلن جاهزة للإطلاق العام قبل اختبار Android TV الفعلي وبيئة الإنتاج. القرار العملي التالي هو تشغيل قبول Android، ثم تنفيذ مزامنة Continue Watching، ثم الانتقال إلى مرحلة الإنتاج والـPilot المحدود.
