# نموذج تشغيل DZ HOOF النهائي

## المبدأ التشغيلي

تطبيق Android هو **عميل مُدار** مرتبط افتراضياً بمنصة `https://iptv.ld-11.net/`. بعد تفعيل الجهاز، يحصل التطبيق من الخادم على جلسة موقعة ورمز قائمة القنوات الخاص بالمستخدم. ولذلك تبقى القنوات، المجموعات، الاشتراكات، الصلاحيات، الأجهزة، EPG، وصحة البث عناصر تُدار مركزياً من الخادم، وليست بيانات مضمّنة في APK.

> لا يُعاد بناء تطبيق Android عند تغيير المحتوى أو إدارة العملاء. يُبنى إصدار جديد فقط عند تعديل كود Android أو تغيير واجهة API بصورة غير متوافقة أو إصدار إصلاح أمني للتطبيق نفسه.

## ما يُدار من الخادم وما يتطلب إصداراً جديداً

| التغيير المطلوب | مكان التنفيذ | هل يحتاج APK جديداً؟ |
|---|---|---:|
| إضافة أو حذف القنوات والفئات والشعارات | لوحة الإدارة وAPI | لا |
| استيراد أو تعطيل مصدر M3U/Xtream مرخّص | الخادم وقاعدة البيانات | لا |
| فحص صحة البث وإخفاء القنوات غير العاملة | المجدول وAPI | لا |
| إضافة دليل البرامج XMLTV أو إصلاحه | الخادم والمصدر المرخّص | لا |
| إنشاء رموز التفعيل وإلغاؤها وتحديد مدة الاشتراك | لوحة الإدارة وAPI | لا |
| تغيير خطة العميل أو الصلاحيات أو حدّ الأجهزة | قاعدة البيانات وAPI | لا |
| إيقاف جلسة أو جهاز أو إعادة إصدار بيانات الوصول | API ولوحة الإدارة | لا |
| تغيير نصوص التطبيق أو واجهة Android أو مشغل الفيديو | مشروع Android | نعم |
| إصلاح أمني داخل APK أو رفع إصدار Android | مشروع Android وإصدار موقّع | نعم |
| تغيير عقد API بطريقة غير متوافقة | API وAndroid معاً | نعم |

## تدفق العميل المُدار

1. يثبّت العميل APK إنتاجياً واحداً بعنوان الخادم الموثوق.
2. يرسل العميل رمز التفعيل إلى مسار التفعيل المركزي عبر HTTPS.
3. يتحقق الخادم من الرمز والخطة وحدّ الأجهزة، ثم يصدر جلسة ورمز قائمة قنوات خاصين بالعميل.
4. يستدعي التطبيق الكتالوج والبث وEPG وبيانات الاشتراك من الخادم في وقت التشغيل.
5. أي تعديل إداري على القنوات أو الاشتراك يصبح متاحاً للعميل بعد التحديث المعتاد للبيانات، من دون تثبيت APK جديد.

## دورة الإصدارات المستقبلية

عند الحاجة إلى تغيير داخل التطبيق فقط، يُرفع التغيير إلى الفرع `main`، ويجب أن ينجح CI في الخلفية والواجهة وAndroid. بعد ذلك يُنشأ إصدار Android موقّع وGitHub Release يحمل رقم إصدار أعلى. يستعلم التطبيق من المسار المركزي `/api/v1/app/version` عن الإصدار الموثوق، ثم يفتح تثبيت التحديث بعد التحقق من توقيعه.

لا تُستخدم نتائج CI المؤقتة كقناة تحديث تلقائية للعملاء. حزم الإنتاج يجب أن تكون موقعة، مرقمة، ومرفقة بإصدار رسمي يمكن للخادم الإشارة إليه.

## ضوابط الأمان والتشغيل

تظل رموز التفعيل ورموز قوائم القنوات وجلسات المستخدم أسراراً تشغيلية؛ لا توضع في Git ولا تُرسل في لقطات الشاشة أو سجلات الخدمة. كل تعديل إنتاجي يبدأ بنسخة احتياطية قابلة للتحقق وفحص صحة بعد النشر. يبقى `mostafabonnif-beep/dzhoot` المستودع الرسمي الوحيد للعمل والإصدارات.
